# DHUM_056905_WW packet notes

Captured on 2026-08-18 from an LG DQ203PECA dehumidifier while it remained registered in the user's ThinQ home.

## Verified cloud controls

ThinQ v2 accepts a single-property control request at the device control endpoint.

- Power uses `ctrlKey=basicCtrl`, `command=Operation`, `dataKey=airState.operation`.
- Target humidity uses `ctrlKey=basicCtrl`, `command=Set`, `dataKey=airState.humidity.desired`.
- `dataSetList` and `dataGetList` are `null` for both forms.

Verified local packets:

| Action              | Packet                             |
| ------------------- | ---------------------------------- |
| Power on            | `01010400000065020100027DC163E3`   |
| Power off           | `01010400000065020100027DC073C2`   |
| Target humidity 50% | `010104000000650201000394D032D182` |
| Target humidity 55% | `010104000000650201000394D0378127` |

The appliance was restored to power off, smart mode 17, fan value 6, and target humidity 55% after testing.

## Verified state fields

| ThinQ field         |     TLV | Conversion                              |
| ------------------- | ------: | --------------------------------------- |
| Operation           | `0x1F7` | 0 off, 1 on                             |
| Operation mode      | `0x1F9` | supported capability bits 17 through 21 |
| Fan strength        | `0x1FA` | enum; this unit accepts only 2 and 6    |
| Target humidity     | `0x253` | 30% through 70%, step 5%                |
| Current temperature | `0x1FD` | raw value divided by 2                  |
| Current humidity    | `0x336` | percent                                 |
| Diagnostic code     | `0x221` | 0 normal                                |

## Verified mode and fan controls

Captured on 2026-08-19 with the appliance powered on. Every packet below was also
produced byte-for-byte by the LG cloud itself when the same change was requested through
`airState.opMode` / `airState.windStrength`, which is how the encoding was confirmed.

| Action                | Packet                             |
| --------------------- | ---------------------------------- |
| Operation mode = fast | `01010400000065020100037E50128988` |
| Fan speed = low       | `01010400000065020100027E824E17`   |
| Fan speed = high      | `01010400000065020100027E860E93`   |

The capability response carries the supported values as bitmaps, one bit per raw value:

| Capability |     TLV | This unit                        |
| ---------- | ------: | -------------------------------- |
| Modes      | `0x2C1` | `0x3E0000` — 17, 18, 19, 20, 21  |
| Fan speeds | `0x2C2` | `0x11044` — 2 (low) and 6 (high) |

Both match `support.airState.opMode` and `support.airState.windStrength` in the model
schema, where the schema numbers the same values one higher. Fan values 0, 4, 7 and 8
were each acknowledged by the appliance and then dropped with no state report, so only
the two bits it advertises are offered.

Observed appliance behaviour worth knowing:

- Selecting silent mode forces the fan to 2 and the appliance reports both changes.
- Changing the fan while in fast mode drops the appliance back to smart mode, which it
  also reports. Fast mode implies its own fan speed.
- `0x2D7`/`0x2D8`/`0x2D9` repeat as a triplet per mode and look like a per-mode fan
  range, but `0x2D9` tracks whatever fan value is currently selected rather than a
  limit. It is not usable as a capability.

The appliance was restored to power off, smart mode, fan high and target humidity 55%
after testing.

## Deferred controls

- Display light, UVnano, water-tank light, melody, air removal, automatic drying, child lock, swing, timers, and filter/energy data are present in the model schema but are not writable in Rethink until each command and rollback is captured.
- Water-tank-full state is defined as TLV `0x186`, but it was not present in the captured normal-state response. Capture a real full-tank event before relying on it.

The Home Assistant implementation exposes power, target humidity, operation mode and fan
speed as writable — exactly the four keys the model schema lists under its `basicCtrl`
control command. Temperature, current humidity and the diagnostic code are read-only.

Mode and fan writes are suppressed while the appliance is powered off, where it
acknowledges them and then ignores them.
