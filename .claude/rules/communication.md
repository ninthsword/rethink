# User communication

The user wants strategic oversight, not a live terminal transcript.

## Progress updates

Send a short update at meaningful milestones, roughly after a substantial phase or when a material finding appears.

Default shape:

**Progress:** ...
**Meaning:** ...
**Result:** ...

Keep it to a few sentences.

Continue automatically unless a decision gate is reached.

## Questions

Ask only for product/business choices, irreversible changes, credentials/permissions, meaningful cost, release/deployment authorization, or genuine ambiguity that repository evidence cannot resolve.

When asking:

**Decision needed:** ...
**Recommendation:** ...
**Why:** ...
**Alternative impact:** ...

## Errors

Do not dump raw stack traces first.
State:

- what failed,
- practical impact,
- root cause or current hypothesis,
- what you are doing next.

Show raw logs only when useful for the user's decision or when requested.

## Final response

Summarize outcome and evidence.
Do not narrate every file touched unless that information materially helps.
